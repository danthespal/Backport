# ps5bp: PS5 game backport toolkit

Python 3.11+, standard library only (the SELF code is vendored, see `vendor/README.md`; GPL-3.0).
Run from the repo root (`E:\PS5_TOOLS\Backport`).

**Whole game** (the main command):

```bash
python -m ps5bp backport GAME_DIR OUT_DIR --firmware 4.03 [--fakelib DIR] [--patch-param] [--stub-nid NID ...] [--stub-unknown] [--define-symbol]
```

- Processes `eboot.bin` and every `.prx`/`.sprx` in the game folder, plus `--fakelib` extras.
  - Extras replace same-named files in the game's `fakelib/`.
  - Unchanged extras are copied verbatim.
- SDK fields are lowered only when they're above the target (Backpork rule).
- `--firmware` takes a minor version: `4.03` → PS5 SDK `0x04030031` (`0xMMmm00pp`, BCD).
- **Known fixes** (`fixes.py`) are applied automatically. They are rules per **system-library function**, not per game, and each lists the console-tested backports it comes from (currently GT7 FW 4 and CONTROL Resonant FW 4.03). Disable them with `--no-known-fixes`.
  - For missing imports: stubs (return 0, fill-out-param, or error return), NID swaps (`MapNamedFlexibleMemoryInternal` → `MapFlexibleMemory`), argument adapters (`SyncOnAddress*` → `_umtx_op`), and a PLT redirect (`qBS714-Jr3g` → libc's own `__cxa_atexit`).
  - **Argument fixes** for functions that exist on old firmware but reject newer values: `sceSaveDataMount3` `systemBlocks -1 → 0` and `sceSaveDataPrepare` `prepareMode 2 → 1`. These replace the per-game call-site patches both games used.
  - Adapter code is branch-free and split across chained int3 caves when needed (eboots only have ≤16-byte padding).
- **Fakelibs come from the per-firmware store** `fakelibs/<FW>/` (exact version first, then the major) when `--fakelib` is not given; `--no-fakelib-store` disables it. Manage it with `python -m ps5bp fakelib add FILES... --firmware 4.03 --source TEXT`, `fakelib list` and `fakelib verify` (see `fakelibs/README.md`). The report names the folder used.
- `--extend-text`: when a module has no int3 padding left, grow its code segment into the unused bytes before the next page (`patch.extend_text`) and place fix code there. Not console-tested; the report notes every extension.
- `--candidate-fixes` also stubs missing imports listed in `candidates.py`. These are reference-derived (AnyPS5 silent stubs, generated by `tools/gen_candidates.py`), not console-proven, for example `sceTextToSpeech2Initialize` → `0x8002002D`. Without the flag, the report shows each available candidate next to the unknown import.
- `--patch-param` lowers `param.json` `requiredSystemSoftwareVersion`/`sdkVersion` to the target, as the Control backport did. By default it is unchanged (GT7 kept it) and a warning is printed.
- The exports of every shipped module count as providers.
- Unknown imports are **reported, not stubbed**, unless `--stub-unknown` is given. With the 3.20 reference that flag may replace functions that do exist on the target.
- `OUT_DIR` receives only changed or added files in the game's layout, which is a ShadowMountPlus overlay (`<scanpath>/backports/<TITLE_ID>/`). It also gets `backport_report.txt` and `backport_report.json`.
- The source folder is never modified, and `OUT_DIR` may not be inside it.
- Each unresolved import in the report shows `refs=N`, the number of direct code references to it (0: reachable only through data, or not at all), and `left unpatched by: GT7/CONTROL` when a console-tested backport shipped it unpatched (`fixes.LEFT_UNPATCHED`).
- The report tags every applied fix **proven** (console-tested backports) or **DERIVED** (references only, or a proven value applied by a new mechanism) and lists the derived ones in a NOTE. It also warns about a stale `ampr_emu.index` (delete it on the console; an overlay can't). Retail-encrypted SELFs stop with a "decrypt first" error.

**Firmware export database** (`firmware_db/<fw>.json`, NID lists only):

```bash
python -m ps5bp fwdb list
python -m ps5bp fwdb import-genstub .original/reference/PS5-3.20_Libs --firmware 3.20 --source "DNNDHH/PS5-3.20_Libs"
python -m ps5bp fwdb import-dump DUMPED_LIB_FOLDER --firmware 13.60 --source "own console dump"
python -m ps5bp fwdb diff 3.20 13.60      # NIDs added between two firmwares
```

`backport`, `report` and `stub` pick the entry for the target firmware: an **exact** database turns absent imports into `missing`; otherwise the highest older firmware is a **lower bound** and absent imports are `unknown`. The report states which was used.

**Fakelib supply** (Phase 3):

```bash
python -m ps5bp fakelib check --firmware 4.03          # imports of the stored set the target may lack
python -m ps5bp bps info .original/reference/BackPork/patches/7xx/*.bps   # what a BPS patch writes
python -m ps5bp bps apply PATCH.bps libSceAgc.sprx OUT.sprx --sign      # 10.01 library -> 6xx/7xx
```

- `fakelib check` classifies each stored fakelib against the target's export list; the set's other fakelibs count as providers. `backport` already runs the same fixes on fakelibs as on game modules.
- `bps apply` checks the source CRC32 (a wrong library version is refused) and the result CRC32. A decrypted SELF input is unwrapped first.
- The manifest records the compiler build date of homebrew modules (`build_date`, e.g. ampr_emu `Aug 24 2026`). `fakelib list` and `backport` warn about builds known to be broken (`store.KNOWN_BUILDS`).

**Single files:**

```bash
python -m ps5bp info FILE...                       # SELF/ELF type, module, SDK fields, import/export counts
python -m ps5bp unwrap game/eboot.bin eboot.elf    # SELF -> ELF (keeps the original ELF header)
python -m ps5bp sdk eboot.elf out.elf --firmware 4 # set the SDK pair (Backpork table, FW 1-10)
python -m ps5bp report eboot.elf --provider fakelib/libSceAgc.elf ...   # import classification
python -m ps5bp stub out.elf out2.elf --nid NH6xARDOVv8 --nid ...       # GOT -> local stub
python -m ps5bp stub out.elf out2.elf --unknown --provider ...           # stub every 'unknown' PLT import
python -m ps5bp sign out2.elf game/eboot.bin       # ELF -> fake-signed SELF (make_fself.py format)
```

`report` classes:

| Class | Meaning |
|---|---|
| `reference` | Exported by the reference firmware (default `PS5-3.20_Libs`, a lower bound for 4.xx) |
| `provided` | Exported by a module shipped with the game (`--provider`) |
| `stubbed` | Already neutralised: the GOT slot points at local code, stub code written into the PLT entry (Control), or the symbol made a local definition |
| `patched` | The PLT entry jumps to a cave or local function (adapter, redirect, argument fix) |
| `data` | Data import; not checkable against stub lists |
| `unknown` | Possibly missing on the target |

`stub` options:
- Stubs are written into `int3` padding directly after a `ret`, leaving a guard byte on each side.
- One stub body is shared by every import that uses it.
- Per-function stub bodies live in `patch.RULES` (for example `sceKernelGetOperationMode` → mode 2, lowEnergy 0); every other import gets `return 0`.
- `--define-symbol` also rewrites the import symbol into a local definition, as GT7's fakelibs do. This is required for RELA (data) imports.

Tests (GT7 samples; skipped when absent):

```bash
python -m unittest discover -s tests -v
```

They verify:
- NID computation.
- SELF round-trip: byte-exact, except the whole-ELF digest when section headers were lost.
- The FW 4 SDK patch reproduces GT7's backported modules byte for byte.
- Stubbing NOT_BACKPORT's eboot reproduces the GT7 backport's behaviour: same stub bodies behind every slot, and no other differences except the not-yet-automated `sceSaveDataMount3` argument patch.
- Import classification of the GT7 fakelibs.
- `backport` on NOT_BACKPORT (FW 4, GT7's fakelibs, GT7's six stub NIDs) produces modules identical to the hand-made GT7 backport for every module that only needs the SDK patch, copies fakelibs verbatim, and reports libc's `SyncOnAddress*` imports.

- The libc fixes reproduce GT7's backported libc: an identical string table (all NID swaps), the same adapter register transforms (each jumping through its own GOT slot with lazy binding intact), the redirect to `__cxa_atexit`, and the same five imports left unknown.

How the libc fixes differ from GT7's hand patch (same behaviour, more general):
- Adapters live in int3 caves, and the PLT entry's first instruction jumps to them. GT7 rewrote four adjacent PLT entries that shared a tail. The cave approach works wherever the imports sit in the PLT.
- The `__cxa_thread_atexit` fix redirects the PLT entry instead of the single call site, so every caller is covered.

`tests/test_control.py` checks that the classifier finds every stub Control's README documents, that `fixes.py` covers all of them, and the 4.03 encodings. A cave-chain test walks the `sceSaveDataMount3` fix from its PLT entry through the caves to its GOT slot.

Audio: instead of Control's Wwise-internal patch, a generic post-call adapter on `sceAudioOut2GetSpeakerInfo` clears the 3D-audio flag and caps the report at 8 speakers, so any game picks 7.1 itself. It is derived from Control's README, its eboot and AnyPS5's struct layout, **not console-tested**. A test walks the chain (PLT → `call` through its own GOT → mask → `ret`).

Fixes marked with only reference sources (no game in `sources`) are derived, not console-proven. Test them on a console before relying on them.
